# cudakit design

cudakit is the CUDA host stack shared by speakrs (diarization) and scriptrs (Parakeet
ASR). It was extracted from speakrs 0.7.0 (`src/inference/cuda`, `xtask/src/commands/cuda_kernels`).

The property every change must keep: **a build needs no CUDA toolkit, and a process
loads only the NVIDIA driver (`libcuda`) plus, when a consumer allows it, cuBLAS,
cuDNN and NVRTC.** It never loads the CUDA Runtime (`libcudart`). That is also why
the crate is not called `cuda-runtime`.

## Crate boundary

Two crates live in this repository:

| Crate | Toolchain | Purpose |
| --- | --- | --- |
| `cudakit` | stable, edition 2024 | Host library: driver context, stream, kernel modules, buffers, GEMM, graph capture, optional cuBLAS/cuDNN |
| `cudakit-build` | stable, edition 2024 | Kernel toolchain as a library: builds cuda-oxide kernels to PTX, pins cubins with ptxas, writes tier crates and manifests, checks them |

Consumers keep, and cudakit never sees:

- their kernels crate (cuda-oxide, pinned nightly, built offline)
- their PTX tier crates (`<consumer>-ptx-sm75`, ...), generated by `cudakit-build`
- their kernel-area enum and its embedded variants
- their model code, plan selection, recipes, tuning and tune-file format
- environment variables: cudakit reads none; consumers read theirs and pass values in

### What moved out of speakrs

| speakrs 0.7.0 | cudakit |
| --- | --- |
| `libraries.rs` (preflight, `OnceLock` handles, TF32 mode lock) | `libraries` (feature `libraries`) |
| `runtime.rs` context, stream, device checks, module cache, cooperative capacity | `Gpu`, `Runtime<K>` |
| `device.rs` `DeviceAttributes` | `DeviceAttributes` |
| `tier.rs` `ComputeCapability`, `PtxTier` | same names; consumer-specific parts move to `Profile` |
| `kernels.rs` hashes, embedded PTX/cubins, `ModuleRequest`, `load_artifact`, `tier_ptx!` | `artifact`, `embed_tier!` |
| `buffer.rs` `DeviceTensor`, `unfold_windows` | same |
| `gemm.rs` + `blas.rs` `Sgemm` | `Sgemm`, plus `SgemmBatched` (new, for scriptrs) |
| `segmentation/graph.rs`, `embedding.rs` and `tuning.rs` capture code | one `Gpu::capture` and `Graph` |
| `dnn/library.rs` conv planner, `geometry.rs` `Conv2d`/`Residual` | `dnn` (feature `libraries`) |
| `tuning/driver_version.rs` | `identity::DriverIdentity` (serde behind feature `serde`) |
| `error.rs` generic variants | `cudakit::Error` |
| xtask `cuda_kernels.rs` + `ptx_lint.rs` | `cudakit-build` |

Stays in speakrs: `KernelModule`, `BoundaryId`, recipes, `candidate/`, `implementation/`,
tuning catalogue and tune-file format, the speakrs policy docs on `CudaMath` and public options, `CudaSession`
(its log lines name speakrs policy), the weights adapter over speakrs's shared
safetensors decoder, and every kernel.

## Public API

```rust
// consumer-wide policy, a const in the consumer
pub struct Profile {
    pub consumer: &'static str,             // names the consumer in messages
    pub compiled: TierSet,                  // GPU target features enabled in this build
    pub shipped: TierSet,                   // tiers with shipped production kernels
    pub tier_features: [&'static str; 4],   // Cargo feature per tier, for error messages
    pub libraries: LibraryPolicy,           // DriverOnly or Allowed
    pub extra_symbols: ExtraSymbols,        // library entry points the consumer calls directly
}

pub trait KernelArea: Copy + Eq + Hash + Debug + Send + Sync + 'static {
    const PROFILE: &'static Profile;
    fn name(self) -> &'static str;          // PTX file stem
    fn variants(self) -> AreaPtx;           // embedded variants in this build
}

pub struct Gpu { /* context, stream, attributes, tier limit, libraries, profile */ }
pub struct Runtime<K: KernelArea> { /* Gpu + module cache keyed by K */ }  // Deref<Target = Gpu>
```

`Gpu` carries everything that does not depend on the consumer's areas, so `DeviceTensor`,
`Sgemm`, conv plans and graph capture take `&Gpu` and are not generic. `Runtime<K>`
adds the module cache:

- `Runtime::<K>::open(ordinal, Options { tier, force_ptx_jit })`
- `runtime.embedded_request(area)` resolves the best runnable embedded artifact
  (exact cubin for this device, else PTX JIT) without loading
- `runtime.load(request)` loads exactly that artifact. A cached module with another
  identity is an error, never a replacement, and a refused cubin never falls back to JIT
- `runtime.load_embedded(area)` does both
- `Kernels::function(name)` looks up an entry point

Errors are one `cudakit::Error` enum. speakrs maps it onto its existing `CudaError`
variants, so speakrs's public error type keeps its shape.

### Driver-only policy

`LibraryPolicy::DriverOnly` makes every cuBLAS/cuDNN/NVRTC request fail with
`Error::LibraryForbidden` before any lookup, and makes `open` fail when the build's GPU
target features cannot serve the device natively. The cudakit `libraries` feature only
decides whether that code exists. Policy is per consumer, not per Cargo feature, so a
binary that links both speakrs (driver-only) and scriptrs (cuBLAS) cannot make speakrs
load cuBLAS through feature unification.

Library loading keeps the speakrs preflight: before cudarc touches a library, cudakit
opens the same file cudarc would pick and checks every symbol cudakit's wrappers or the
consumer's `extra_symbols` call. A missing symbol is `Error::LibraryUnavailable`, never
a panic inside cudarc, and never a silent fall-through to another version.

### Kernel areas and PTX tier crates

A consumer:

1. Owns `crates/<consumer>-cuda-kernels` (cuda-oxide; one Cargo feature per area,
   cumulative `tier-sm80`/`tier-sm90`/`tier-sm120` features) and one
   `crates/<consumer>-ptx-<tier>` crate per shipped tier. `cudakit-build` generates the
   tier crates' `lib.rs`: `no_std`, no dependencies, two `const fn` lookups (`ptx`,
   `cubin`). They do not depend on cudakit, so publishing them never pins a cudakit
   version.
2. Writes two `const fn` lookups, `shipped_ptx` and `shipped_cubin`, that chain its
   enabled tier crates, and a one-line local `tier_ptx!` wrapper over
   `cudakit::embed_tier!`. Lookups must stay in const context: a run-time call links
   every file of every enabled tier crate into the binary (fixed in speakrs 0.7.0).
3. Implements `KernelArea` for its area enum with `variants()` built from `tier_ptx!`
   calls and marked `#[inline(never)]` so codegen units do not each copy the bytes.
4. Declares a const `cudakit_build::Project` in its xtask and forwards its subcommands to
   `Project::{build, build_cubins, check}`.

### Graph capture

`unsafe fn Gpu::capture(enqueue) -> Result<Option<Graph>, E>` with
`E: From<cudakit::Error>`. It is `unsafe` because the graph keeps raw pointers to the
captured buffers, and nothing in the types ties them to `Graph::launch`: the caller
guarantees every launch finds them allocated in place. Dropping a graph only destroys
its driver handles, so a consumer may keep a stale graph that can no longer be launched
(speakrs's embedding storage does this with a generation token). It synchronizes the
stream, pauses cudarc event tracking (required, or capture fails with
`CUDA_ERROR_STREAM_CAPTURE_ISOLATION`), captures thread-locally, ends the capture even
when `enqueue` returns an error (a panic unwinds without ending it), and restores
tracking. The driver ends an empty capture with a zero-node graph rather than none, so
`capture` counts nodes and returns `None` for empty work; `capture_nonempty` makes that
`Error::EmptyCapture`. `Graph::launch` replays on the same stream. This replaces three
copies in speakrs. `Graph::as_cuda` exposes the cudarc graph for consumers that add
conditional nodes later.

## What scriptrs needs (Phase 3 in its plan)

- **GEMMs.** `Sgemm` (row-major over `cublasSgemm`, TF32 mode lock) and new
  `SgemmBatched` (`cublasSgemmStridedBatched`) for per-head attention products. Both
  check buffer lengths against dimensions. FP16/BF16 `cublasGemmEx` is not in the first
  API; add it when scriptrs has a measured need.
- **Whole-encoder graph.** Allocate persistent `DeviceTensor`s per fixed chunk shape,
  run the encoder once eagerly so cuBLAS finishes lazy setup, then
  `unsafe { gpu.capture(|| encoder.enqueue(&gpu)) }` and `graph.launch()` per chunk
  batch.
  Prepare cuBLAS (`gpu.prepare(Library::Cublas)`) at model load, never inside capture.
- **TDT decode on device.** First version: capture one decode step (predictor LSTM,
  joint, argmax, duration advance) as a graph and replay it without host syncs, reading
  results once per chunk. The step's control state lives in device buffers. Conditional
  graph nodes (CUDA 12.4 floor allows them) or a persistent kernel come later and need
  only `Graph::as_cuda` plus its own kernels.
- **Own kernels crate.** `scriptrs-cuda-kernels` plus `scriptrs-ptx-<tier>` crates,
  configured by a `cudakit_build::Project` in the scriptrs xtask. Its `KernelArea` enum
  has its own `Profile` (`libraries: Allowed` while it is library-first).

## Kernel toolchain: library, not a copied script

`cudakit-build` is a library that consumers' xtasks call. A standalone binary would need
its configuration in a file and would hide the pinned rev from code review; a copy would
let the two consumers' pins and checks drift. The library owns the generic machinery
(variant builds, ptxas pinning, cubin manifests, header and entry-point checks, PTX lint,
tier-crate rendering, host embed-mask check). The consumer's `Project` supplies:

- kernel crate, manifest directory, host file with `tier_ptx!` calls, tier-crate path pattern
- areas with their tiers and binding flags (`pinned_baseline`, `bound_top`)
- cuda-oxide rev and nightly, `MAX_PTX_ISA` (9.0 so driver 580 can JIT), ptxas version,
  cubin architectures
- the host feature name pattern (`cuda-{tier}`)

The pins stay per consumer on purpose: speakrs kernels must not rebuild because scriptrs
moved to a newer cuda-oxide. `cudakit-build` provides defaults for the current pins.
`scripts/setup-gpu-box.sh` (CUDA 13, LLVM 21, nightly, cuda-oxide) moves here.

## Workspace layout and features

```
cudakit/
  Cargo.toml              workspace, edition 2024, stable
  crates/cudakit/         host crate
  crates/cudakit-build/   kernel toolchain library
  docs/design.md
  scripts/setup-gpu-box.sh
  HANDOFF.md
```

`cudakit` features, mirroring speakrs's `_cuda` / `_cuda-libraries` split:

| Feature | Adds |
| --- | --- |
| (none) | driver API only: `cudarc` with `driver`, `nvrtc` (for the `Ptx` type; NVRTC is not loaded), `dynamic-loading`, `cuda-12040` |
| `libraries` | `cudarc/cublas`, `cudarc/cudnn`, the preflight, `Sgemm`/`SgemmBatched` execution, `dnn` |
| `serde` | serde for `DriverRelease` |

Consumers make cudakit an optional dependency enabled only by their CUDA features, so CPU
and CoreML builds stay free of cudarc.

## Decisions taken without Praveen

- Policy (driver-only) is a runtime `Profile` value, not a cudakit Cargo feature, for the
  feature-unification reason above.
- `CudaMath` becomes a documented re-export of `cudakit::Math`, which is exhaustive:
  speakrs persists the mode in tuning keys and matches it across the crate boundary,
  which a `#[non_exhaustive]` foreign enum forbids. A separate speakrs enum would need
  conversions at about 30 geometry sites that also read the mode back. speakrs's
  `CudaMath` loses `#[non_exhaustive]` (a semver-compatible relaxation; adding a mode
  later is breaking). `ComputeCapability`, `PtxTier` and `CudaLibrary` become
  re-exports and stay `#[non_exhaustive]`;
  `PtxTier::{feature, compiled_in, is_compiled_in, select, native, from_env, SHIPPED}`
  move to speakrs-side helpers because they encode speakrs features and env vars. That
  is a public API change for speakrs and needs a CHANGELOG entry before release.
- The tune file stays in speakrs; only the driver release reader moves.
- `Gpu` and `Runtime<K>` are `Send + Sync` (asked for by scriptrs, whose model moves to
  worker threads behind a mutex). cudarc's `Cudnn` is `!Send + !Sync` and cuDNN forbids
  one handle on two threads at once, while cudarc's descriptors each keep a clone of it.
  Rather than one handle per planner (an extra `cudnnCreate` per speakrs conv plan,
  unmeasured because the GPU box has no cuDNN), the shared handle is thread-affine:
  `Gpu::dnn` returns it only on the thread that prepared cuDNN, so its `!Send` clones
  never leave that thread. speakrs prepares and uses cuDNN on one worker thread, so its
  behavior is unchanged. `Graph` is `Send` only, since CUDA forbids launching one
  executable graph from two threads at once. A context is current per thread, and
  cudarc binds it for allocations, copies, launches and graphs but not for cuBLAS,
  cuDNN, function lookup or occupancy queries, so cudakit binds before each of those
  and before the library handles are destroyed in `Gpu`'s drop.
